# Source compatibility fixtures

`release.json.gz`, `installed.json.gz`, `v0748.json.gz`, `v0764.json.gz` and `v0765.json.gz` are gzip-compressed JSON maps of finite relative paths to raw UTF-8 upstream file contents, not executable test modules. The earlier fixtures were fetched from `https://raw.githubusercontent.com/orbi-build/orbi/<commit>/<path>` during implementation; v0748, v0764 and v0765 were built with `git cat-file blob <commit>:<path>` from their tagged commits. Tests unpack them into isolated temporary directories and run the production bounded filesystem reader, contract-facts reader and hash gate, never import or execute the Python source.

- installed: `1a8b2f9603f6258cb105293f238a8d3f775f3393`, subset aggregate `ae5bd552aef7e1689b7352d99794f6dc0a04e257cf3668cad08be9473b9d859d`
- v0748: `f405e1dc4ff938ab99ec0742cfd3459d45e26948`, subset aggregate `f7d966479d4121b3cebecc116dd723eb0d0c7e2198d535b460230d06e118678e`. `v0748.json.gz` uses the same format as the earlier fixtures and contains the subset paths below.
- v0764: `fbc76f57c79f21b90678adbbbaeef5f0825fdb57` (tag v0.7.64), contract-facts SHA-256 `1831c77a488fd75c93fbd24442b8d62c95410dc93a5553e404680caab38e7343`, `src/orbi/runner_health.py` SHA-256 `01f882378aee9a59ed50ac8e98b50a9fe81dc1d02b53a86dd0746257fb645f79`, `src/orbi/run_state.py` SHA-256 `00d8a40a8de85a3d19186928a82bb4c56a58d356c301a024dcb9a1432f8d1653`. `v0764.json.gz` contains only the contract-fact files and the two writers, built with `git cat-file blob <commit>:<path>`.
- v0765: `a37c005cd2ff1657715ea11426ea1d8bbf9d09b2` (tag v0.7.65), contract-facts SHA-256 `1831c77a488fd75c93fbd24442b8d62c95410dc93a5553e404680caab38e7343`, and the same two writer SHA-256 values as v0764. `v0765.json.gz` uses the format below from the tagged v0.7.65 commit; its former subset path set had aggregate `d1410b7b18ef41b838f9a1ec4aba4d807c6c0a8a8f348f37a358e8bea887040d`, which is no longer used for admission.

Release paths are exactly `docs/public-contracts.mdx` and `src/orbi/{base_ci_red,config,delivery_labels,failure,journal,pi_activity,run_state,runner_health,scene,scheduler_units,status_observe}.py`; installed additionally includes `src/orbi/worktree_retention.py`. v0748 includes the installed paths plus `src/orbi/{blocked_record,comment_kind,progress,question,requeue}.py`, pinning the stop-record prefix, comment envelope, progress, question/answer and requeue marker producers. This does not authorize answering or requeueing. v0765 includes the v0748 paths plus `src/orbi/labels.toml`, which carries the label names the plugin classifies.

For a **subset** profile, sort paths lexicographically, concatenate `path + NUL + lowercase hex SHA256(raw bytes) + LF`, and SHA256 that UTF-8 manifest. For the **contract** profile `orbi-0.7.65-release`, the contract-facts reader normalizes the facts from `src/orbi/{labels.toml,failure,progress,question,base_ci_red,scene,comment_kind,requeue,blocked_record,journal,config,worktree_retention,scheduler_units,status_observe}.py` into a sorted `<kind> <value>` manifest, and its SHA-256 must equal the pinned facts digest; the whole-file SHA-256 of `src/orbi/runner_health.py` and `src/orbi/run_state.py` must also match. Other engine files may differ, so v0.7.64 and v0.7.65 fixtures both pass. `src/orbi/provider_balance.py`, which owns the v0.7.65 `provider_balance`/`top_up_balance` codes, is deliberately absent from every pinned set: `server/read-ports.ts` refuses any path segment matching `/provider/i`, so it cannot be read by the gate. Those codes are closed enums in `shared/issues.ts`, so a changed code fails validation rather than passing the gate unnoticed.

A contract profile is compatibility evidence for the listed contract facts and the two writer files only, not for the rest of the engine and not authentication of any whole engine. Accepted limit: an engine behavior change with unchanged facts and writer bytes is not detected; a structural change to those facts or writers makes the contract-facts reader refuse or changes a pinned hash, so the deployment is rejected as `unsupported_source_profile`.

`host.ts` mocks only Paseo/RN modules. `environment.ts` supplies React Native's window-without-DOM host global before QueryClient initialization. QueryClient, configuration, read ports, hashing and RPC contracts themselves are not mocked.
